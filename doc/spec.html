🚀 Project Specification

TonyGitLens Specification

Architectural survey of GitLens and detailed technical specification for TonyGitLens — a focused, high-performance VS Code extension for exploring Git Worktrees and their commits.

Executive Summary

Developers using Git Worktrees frequently operate across multiple working directories linked to the same repository. While GitLens offers extensive Git capabilities, it is often considered heavyweight. TonyGitLens isolates the most valuable worktree functionality: effortless visual switching, branch and HEAD status tracking, deep commit exploration per worktree, and zero-latency side-by-side file diffs.

🌲 Worktree TreeView

Displays main & linked worktrees, active checkout flags, branch tracking, and lock indicators in VS Code's sidebar.

📜 Commit History per Worktree

Expand any worktree to instantly review its commit history with author, relative timestamps, and short SHAs.

🔍 File Diffs via Virtual URI

Inspect changes per commit using native VS Code diff views powered by a custom tonygitlens:// provider.

⚡ Lightweight & Fast

Scaffolded with TypeScript and esbuild; utilizes native Git CLI streaming and lazy loading for instantaneous responsiveness.

Part 1: Survey of How GitLens Works

1. Dual Git Integration Layer

GitLens avoids heavy JavaScript Git implementations (such as isomorphic-git) because they cannot match the performance and feature set of the native git binary. Instead, GitLens employs a hybrid model:

  • VS Code Git API (vscode.git): Registers listener hooks via vscode.extensions.getExtension('vscode.git')?.exports.getAPI(1) to react when repositories are opened, closed, or switched.
  • Native Git CLI Process Runner: Spawns asynchronous git processes with streaming buffers (child_process.spawn / execFile) for heavy operations like log parsing, worktree inspection, and commit content extraction.
Key Insight for TonyGitLens

Using the native Git CLI directly gives us 100% compatibility with worktree configurations, submodules, GPG signing, and custom Git hooks without adding bloated dependencies.

2. Worktree Discovery & State Parsing

GitLens inspects worktrees using Git's machine-readable porcelain format:

git worktree list --porcelain

The porcelain format outputs structured stanzas separated by empty lines:

worktree /home/user/project/main
HEAD 4f88e1462002cbce7c10
branch refs/heads/main

worktree /home/user/project/feature-auth
HEAD 118a72b0cde8823190ab
branch refs/heads/feature-auth
locked in-progress refactoring

From this format, GitLens extracts:

  • Main vs. Linked Worktree: The first entry is always the primary worktree containing the .git directory; subsequent entries contain a .git file pointing to the main gitdir.
  • Branch & Detached State: If a worktree is checked out to a tag or commit SHA, detached is reported instead of a branch ref.
  • Lock Status: Reports if a worktree is locked against pruning or removal, along with any optional lock reason.

3. High-Performance Commit Parsing

To avoid parsing arbitrary text that might break when commit messages contain special characters or newlines, GitLens invokes git log using custom NUL-delimited (%x00) formats: 

git -C <worktree-path> log -n 25 --format="%H%x00%h%x00%an%x00%ae%x00%at%x00%s%x00%P"

The output is split strictly by \0 delimiters, enabling robust extraction of the full hash, short hash, author name, author email, Unix timestamp, subject line, and parent hashes without regex guesswork.

4. Virtual Document Provider for Diffs

To display historical file contents without creating temporary files on disk, GitLens registers a vscode.TextDocumentContentProvider on a custom URI scheme (e.g. gitlens://).

When diffing a file in a commit against its parent:

  1. TonyGitLens creates two virtual URIs:
    • Left URI: tonygitlens://commit/{parentSha}/{path}?worktree={worktreePath}
    • Right URI: tonygitlens://commit/{targetSha}/{path}?worktree={worktreePath}
  2. VS Code calls provideTextDocumentContent(uri) for each URI.
  3. The provider executes git -C <worktree> show <sha>:<path> and delivers the file content.
  4. VS Code opens its native diff editor: 
    vscode.commands.executeCommand('vscode.diff', leftUri, rightUri, `${fileName} (${shortSha})`);

5. Lazy-Loaded TreeView Pattern

VS Code's TreeDataProvider only resolves child items when an item is expanded in the UI. GitLens leverages this so that:

  • Root level only queries git worktree list --porcelain (~1-5 ms).
  • Expanding a Worktree queries the top 20 commits for that worktree.
  • Expanding a Commit queries modified files via git show --name-status <sha>.
  • Result: Near-zero memory footprint and instantaneous startup.

6. Reference & Branch Comparison in GitLens

GitLens provides a dedicated Search & Compare view that lets users compare any two Git references (branches, tags, or commits). Understanding how GitLens implements this:

  • Comparison Semantics:
    • Two-Dot Comparison (base..compare): Shows what is unique to the compare branch that is not in the base branch.
    • Three-Dot Comparison (base...compare): Compares the tips of both branches starting from their common merge-base ancestor (git merge-base base compare). This matches what developers expect when opening a Pull Request.
  • File Diffs Query: Executes git diff --name-status <base>...<compare> to retrieve the exact list of files modified, added, deleted, or renamed between the branches.
  • Commit Difference Query: Executes git log <base>..<compare> to retrieve the commits that exist on the compare branch but not the base branch (ahead commits), and optionally git log <compare>..<base> (behind commits).
  • Interactive Controls: GitLens provides quick actions to Swap References (switch base and target), Select New Branches via QuickPick, and click-to-diff each changed file using VS Code's side-by-side diff editor.

2. Core Data Models

TypeScript interfaces defined in src/models/git.ts:

export interface Worktree {
  path: string;             // Absolute filesystem path
  head: string;             // Full commit hash (HEAD)
  branch?: string;          // e.g. "refs/heads/main" or "main"
  isMain: boolean;          // Primary working tree vs linked worktree
  isCurrent: boolean;       // Matches current active VS Code workspace folder
  isLocked: boolean;        // Locked against pruning
  lockReason?: string;
  isDetached: boolean;      // Detached HEAD state
}

export interface Commit {
  hash: string;             // Full 40-char SHA
  shortHash: string;        // 7-8 char SHA
  authorName: string;
  authorEmail: string;
  date: Date;
  subject: string;
  parents: string[];
  worktreePath: string;
}

export interface CommitFileChange {
  status: 'A' | 'M' | 'D' | 'R' | 'C' | 'U';  // Added, Modified, Deleted, etc.
  path: string;             // Relative path in repository
  originalPath?: string;    // In case of rename/copy
  commitHash: string;
  worktreePath: string;
}

6. Compare 2 Branches Specification (Phase 6)

In GitLens, comparing branches is context-anchored directly to the Worktree UI. When a user looks at a worktree in the sidebar, the base branch is already known. Rather than requiring two separate selection dialogs, GitLens provides an inline "Compare with..." action on each worktree row so the user only has to pick a single target branch.

GitLens-Inspired 1-Selection Workflow
  1. Contextual Trigger: Click the inline $(git-compare) icon or right-click any Worktree item (e.g., feature-auth) → select "Compare with...".
  2. Implicit Base: The base branch is automatically locked to feature-auth.
  3. Single Target Selection: A single QuickPick appears displaying all local & remote branches (e.g. main, develop, staging).
  4. Instant Comparison: As soon as the target branch is picked, the comparison displays the differences immediately.

8. Loading & Installation Guide

TonyGitLens is packaged as a self-contained .vsix extension bundle, making it immediately installable in any VS Code desktop or remote environment.

🎉 Primary Method (Tested & Verified Working)

Option A — Right-Click VSIX in VS Code Explorer:

  1. In your VS Code file explorer sidebar, navigate to tonygitlens-0.1.0.vsix.
  2. Right-click the file and select "Install Extension VSIX".
  3. VS Code installs the extension immediately. The TonyGitLens icon appears in your Activity Bar and in the Source Control panel!

⌨️ Option B: Command Palette

Press Ctrl+Shift+P (or Cmd+Shift+P), type Extensions: Install from VSIX..., and select tonygitlens-0.1.0.vsix from the file picker.

💻 Option C: Terminal Command

Run the standard VS Code CLI command in your terminal: 

code --install-extension /home/tonyho/workspace/vscode_ext/tonygitlens-0.1.0.vsix

🐞 Option D: Developer Debug Mode (F5)

For active extension development and debugging:

  1. Open the extension project folder in VS Code.
  2. Press F5 (or select Run > Start Debugging).
  3. VS Code launches an isolated Extension Development Host window using the configured extensionHost launch profile.

Packaging Command Reference

To rebuild the .vsix package after making code changes, run:

npx @vscode/vsce package --no-dependencies --allow-missing-repository
